# 항목별 작성 기준

SSAFY IT 포트폴리오 가이드의 "항목별 주요 내용"을 정리한 것이다. 항목마다 쓸 것, 피할 것, 예시를 둔다. 예시는 형식 참고용이며 내용은 항상 사용자의 재료로 채운다.

## 목차
1. 프로필: 슬로건 / 한 줄 소개 / 기술 스킬
2. 이력사항: 교육 · 수상 · 자격증
3. 프로젝트: 개요 / 담당 역할 · 기여도 / 사용 기술 / 문제 해결 사례
4. 점검표

---

## 1. 프로필

### 슬로건: 나를 정의하고 어필하는 한마디

쓸 것
- 직무와 연관된 나의 강점 · 보유 역량
- 구체적인 수식어
- 나와 잘 어울리는, 나를 떠올리게 하는 단어

피할 것
- "끊임없이 학습하는 개발자", "도전하는 개발자"

### 한 줄 소개: 현재의 나와 지향하는 바

쓸 것
- 개발자로서 지금의 가치관
- 단기 · 중장기 목표
- 가장 깊이 있게 구현 중인 스킬

피할 것
- "새로운 기술 학습을 좋아합니다", "소통을 잘합니다"

예시
> **"데이터로 답을 찾는 분석형 개발자"**
> 데이터 기반의 문제 해결을 지향하며, Python과 SQL을 통해 데이터 분석 및 백엔드 개발 역량을 강화하고 있습니다.

> **"확장성과 안정성을 추구하는 클라우드 개발자"**
> 안정적이고 확장 가능한 시스템 구축을 위해, 클라우드 환경(AWS)과 컨테이너 기술(Docker)을 학습하고 있습니다.

### 기술 스킬: 활용할 수 있는 스킬을 한눈에

핵심 질문은 **"그래서 그걸로 무엇을 할 수 있는데?"** 다.

쓸 것
- 스킬을 카테고리로 묶기 (FrontEnd, BackEnd, DB, Infra 등)
- 숙련도를 시각화 (단계, 막대 등)
- 주요 스킬마다 활용 수준을 문장으로

피할 것
- 숙련도를 전부 상 또는 전부 하로 표시
- 스킬 이름만 나열 ("BackEnd : JAVA, Kotlin, Spring Boot, MySQL")

예시
- React
  - React Router로 간단한 SPA 구축
  - API를 호출해 받은 데이터를 화면에 렌더링
- JavaScript
  - 모듈 단위로 코드를 나누고 ES6+ 문법으로 유지보수하기 쉬운 코드 작성
  - 테스트 코드(TDD)로 코드 안정성 확보

숙련도 정하기: 사용자가 판단하기 어려워하면 스킬마다 5단계 기준을 세우고, 사용자의 프로젝트 경험에 비추어 한 단계를 고르게 한다. 근거가 된 경험을 함께 적어 두면 과대 · 과소 평가를 막을 수 있다. 가이드의 MySQL/MariaDB 예:

1. 기초: DB 설치, 간단한 테이블 생성, 데이터 삽입 · 조회 SQL
2. 초급: 기본 SQL 쿼리로 데이터 관리
3. 중급: JOIN을 활용한 복잡한 조회, 기본적인 DB 설계
4. 상급: 인덱싱과 트랜잭션으로 성능과 데이터 무결성 보장
5. 전문: 고급 쿼리 최적화, 복제(replication), 샤딩(sharding)으로 대규모 DB 관리

## 2. 이력사항

### 교육 경험: 도전의식, 전문성, 성장 의지를 드러낸다

쓸 것
- 직무 · 강점과 관련된 경험 (수상, 교육 수료, 자격증 등)
- 경험마다 간단한 설명
- 구체적인 기간, 시간, 습득한 내용

피할 것
- "SSAFY 재학 중, 공통/특화/관통 프로젝트 수상": 바깥 사람은 무슨 내용인지 알 수 없다

모르는 사람이 봐도 이해되게 쓴다. 이력이 슬로건과 한 줄 소개를 뒷받침하면 더 좋다.

고쳐 쓰기 예
- "특화 프로젝트 우수상" → "시니어를 위한 금융앱 개발 프로젝트 / 우수상"
- "SSAFY 수료" → "삼성청년SW·AI아카데미 수료: Python, SQL 등 ○○ 지식 · 스킬 습득, 팀 프로젝트 수행"

형식 예
```
Awards / Certificates
2025.9.  시니어를 위한 금융앱 개발 프로젝트 / 우수상 / SSAFY
2025.8.  ○○은행 주최 해커톤 / 최우수상 / ○○은행
2025.3.  SQLD 취득

Education
2025.1.2. ~ 12.31.  삼성청년SW·AI아카데미 수료
 - Java 알고리즘, Spring · Vue 실습 기반 웹 풀스택 학습
 - 7주 팀 프로젝트 3회 수행
 - AI 기능 · 모델링 · 파인튜닝 실습 특강 50시간 이수
```

## 3. 프로젝트

### 프로젝트 개요: 목표, 배경, 주요 기능

- 프로젝트의 배경 / 대상자 / 목표
- 주요 기능은 키워드 중심으로, 기능마다 한 줄 설명

### 담당 역할 · 기여도: 본인이 참여한 내용이 핵심

쓸 것
- 프로젝트에서 맡은 역할
- 기여한 내용과 비율을 구체적으로
- 본인이 기여한 항목은 따로 한 번 더 강조

피할 것
- "파트를 분배하여 협력함"
- 팀 발표 자료를 그대로 옮기기

### 사용 기술: 어떤 기술을 왜 썼는가

쓸 것
- 사용한 기술
- 그 기술을 고른 이유

피할 것
- "○○ 분야의 최신 기술을 적용"

예: Spring Boot — 대규모 트랜잭션을 안정적으로 처리하고 Spring Cloud Gateway 같은 확장 프레임워크를 지원해서 선택

구성 예시
```
안전한 금전 거래를 위한 자동 관리 플랫폼
개인 간 금전 거래를 자동화해 안전하게 진행되도록 돕는 서비스. (한두 문장)

▪ 주요 기능
 - 거래 계약 및 관리: (한 줄 설명)
 - 주요 이벤트 알림: 거래 완료, 예약 일정 등
 - 거래 목록 시각화 및 조건 필터: 조건별 내역 검색
▪ 담당 역할 및 기여도
 - 계약 목록 시각화 및 필터링: (무엇을 어떻게)
 - 계약 상세 페이지 / 실시간 알림 페이지: (무엇을 어떻게)
▪ 기술 스택
 - Spring Boot: (고른 이유)
```

### 문제 해결 사례: 경험에 기반한 나만의 해결 방법

구조: **문제 인식 → 해결 방안 → 개선 성과**

쓸 것
- 문제 인식: 프로젝트 중 생긴 문제를 설명
- 해결 방안: 해결 방법과, 그 방법을 고른 이유
- 개선 성과: 내가 구현한 기능 중심으로. 개선된 수치처럼 객관적이고 구체적인 변화를 제시. 수치가 없으면 구체적인 방법으로 정성적 성과를 쓴다 (예: 팀 코드 컨벤션을 정립해 불필요한 코드 축소)

피할 것
- "캐싱 전략으로 문제 해결": 무엇이 문제였고 왜 캐싱인지가 빠졌다
- "팀원과의 적극적인 소통으로 문제 해결"

꼭 "문제"가 아니어도 된다. 성능 개선을 위해 고민한 것, 새로 배워 적용한 기술 같은 "도전 사례"도 좋다. 그래프, 테스트 결과, UI 이미지로 변화를 눈으로 보여 주면 더 좋다.

예시
- 문제 인식: 과도한 학습으로 loss 값이 NaN으로 측정됨 / 라우팅이 불안정해 앞 · 뒤로 가기 때 상태가 사라짐
- 해결 방안: learning rate를 0.02 → 0.01로 조정 / 단계별로 필요한 데이터 타입을 명확히 정의
- 개선 성과: 종류 구분 정확도 80% → 94% / 타입 기반 컨텍스트로 유지보수성 향상

## 4. 점검표

수정 단계에서 차례로 확인한다. 걸리는 항목은 고치거나 `[확인 필요]`로 남긴다.

전체
- [ ] 슬로건 · 한 줄 소개의 키워드가 이력과 프로젝트에서 실제로 증명되는가
- [ ] 나열이 아니라 성장 과정이 읽히는가 (무엇을 겪고 어떻게 나아졌는지)
- [ ] 교육 과정 내부 용어, 설명 없는 약어가 없는가

프로필
- [ ] 슬로건과 한 줄 소개가 누구에게나 붙는 말이 아닌가
- [ ] 기술 스킬마다 "그걸로 무엇을 할 수 있는지"가 있는가
- [ ] 숙련도가 전부 같은 단계로 몰리지 않았는가

이력사항
- [ ] 항목마다 날짜, 이름, 결과(상 · 등급), 주최 · 기관이 있는가
- [ ] 교육에 기간, 시간, 배운 내용이 있는가

프로젝트 (프로젝트마다)
- [ ] 배경 · 대상 · 목표가 있는가
- [ ] 내 역할과 기여도가 구체적인가 (기능 · 화면 · 비율)
- [ ] 기술마다 고른 이유가 있는가
- [ ] 문제 해결 사례가 문제 → 해결 → 성과를 모두 갖췄는가
- [ ] 성과에 수치나 전후 비교, 또는 구체적인 정성적 근거가 있는가
- [ ] 보여 줄 자료(화면, 그래프, 다이어그램, 영상)의 자리가 있는가

표기
- [ ] 오타, 띄어쓰기
- [ ] 기술 이름 표기 통일 (Spring Boot / SpringBoot, JavaScript / Javascript 등)
- [ ] 날짜 형식 통일
- [ ] 문장 끝맺음 통일 (~습니다 / ~함)
