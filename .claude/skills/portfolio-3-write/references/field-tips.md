# 지원 분야별 작성 팁

SSAFY IT 포트폴리오 가이드의 지원 분야별 팁이다. 지원 분야에 해당하는 부분만 읽는다. 분야가 둘 이상이면 (예: 풀스택) 해당 부분을 모두 읽고 지원처가 더 중시하는 쪽을 앞에 둔다.

모든 분야 공통: **개선 · 최적화 결과는 수치와 근거를 함께, 바꾸기 전과 후를 같이 보여 준다. 그 방법을 고른 이유도 쓴다.**

## 목차
- 프론트엔드
- 백엔드
- 임베디드
- AI / 데이터
- 모바일

---

## 프론트엔드

강조할 것
- **반응형 웹과 렌더링 최적화**: 여러 기기에서 쓸 수 있는 반응형 웹. 코드 스플리팅, Lazy Loading, 이미지 최적화 같은 렌더링 최적화로 사용자 경험을 개선한 사례
- **상태(데이터) 관리**: 사용자 상호작용에 따라 바뀌는 상태를 어떤 전략으로 관리했는지. API 성능 개선, 데이터 처리 경험
- **비주얼과 UI/UX**: 프로젝트 화면 이미지를 넣고, UI/UX를 고려한 디자인과 피드백을 반영한 과정을 보여 준다. 다른 직무보다 포트폴리오 자체의 가독성도 중요하게 본다

예시
- Lazy Loading으로 번들 크기 최적화
  - 이슈 진단: 모든 페이지를 초기 번들에 넣어 첫 로딩 때 리소스가 과다해 성능 저하와 사용자 불편
  - 이슈 해결: 사용자 접근 빈도에 따라 동적 import로 나누고, 데이터 요청을 컴포넌트별 Suspense fallback에 연결
  - 결과: 청크 크기 62% 감소, 빌드 시간 35% 단축, 성능 점수 개선
- FCM 기반 실시간 알림 성능 개선
  - 이슈: 전체 데이터를 한 번에 불러와 알림 페이지 초기 속도 저하
  - 해결: 무한 스크롤 도입, 확인 전 알림 우선 노출
  - 결과: 초기 로딩 성능 개선, 필요한 정보에 바로 접근

## 백엔드

강조할 것
- **최적화와 확장성**: 계속 업데이트되는 서비스가 사용량 변동에도 속도 · 성능을 유지하도록 한 경험. 로드 밸런싱, 트랜잭션 처리, 컨테이너 관리
- **테스트 코드와 보안**: 동작을 넘어 신뢰할 수 있는 코드를 쓰는 역량. 보안 적용 사항, 취약점 해결 경험
- **아키텍처 설계**: DB 관리와 로직 설계 역량은 필수. API 설계, 데이터베이스 모델링, 서비스 구조 설계를 시각화 자료와 함께

예시
- 복잡한 백그라운드 로직을 플로우 차트, 유스케이스 다이어그램으로 시각화해 공유 → 새 팀원도 빨리 적응
- Firestore → MySQL로 DB 이전 + 실시간 데이터 처리를 위해 Redis 도입 → 안정성과 성능 확보 (바꾸기 전의 문제나 개선 수치를 함께)
- 실시간 잔액 처리와 보안 설정 개선
  - 기존: 잔액을 DB에 저장해 외부 입출금이 반영되지 않음 → 잦은 데이터 불일치, 대출 승인 · 상환 때 실제와 시스템 판단이 달라 오작동
  - 해결: 금융망 API로 실시간 잔액을 확인하도록 바꿔 DB를 단순화하고 정합성 향상. API Key, 인증 정보 같은 민감한 값은 환경 변수로 분리해 관리

추가 팁: 교육 과정 안에서만 쓰는 말 대신 바깥에서 통하는 표현을 쓰고, 개선은 전 · 후를 같이 보여 준다.

## 임베디드

강조할 것
- **성능 최적화와 전력 효율**: 제한된 자원으로 특정 작업을 하므로 저전력 모드, 메모리 · 타이머 최적화, 인터럽트 처리 같은 경험이 중요
- **회로도 · 데이터시트 분석**: SW 엔지니어도 기본 이해는 필수. 개발한 시스템의 실제 사진, 작동 영상, 데이터시트 분석을 넣어 신뢰도를 높인다
- **하드웨어 연동**: 센서, 장치 드라이버 활용, RTOS 지식, 통신 인터페이스(UART, I2C, SPI 등) 경험

예시
- 프로젝트: 초음파 센서를 활용한 거리 측정 TI 부스터팩
- 담당: HW 설계 · 제작, MCU 모듈 간 통신 SW
- 핵심 구현: MCU(TM4C123GH6PM) 기판에 붙는 부스터팩 HW 구현, 부스터팩과 MCU 간 통신 구현, 블루투스 동작 확인용 샘플 안드로이드 앱

추가 팁: 실제로 작동하는 영상을 첨부하면 좋다.

## AI / 데이터

강조할 것
- **데이터 전처리와 파이프라인**: 전처리는 모델 성능과 정확도를 좌우한다. 비정형 데이터의 수집 · 변환 · 정제를 자동화한 파이프라인 경험
- **실제 적용 사례와 개선 포인트**: 모델이 실제 서비스에 쓰인 결과, 개선 전후 지표. 지표는 Confusion Matrix, ROC Curve 등으로 시각화
- **모델 성능과 평가 지표**: 신뢰성 · 안정성을 검증하는 과정. 성능 수치와 함께 개선을 위해 쓴 기법

예시
- Celery로 작업 안정화: 파라미터 조정으로 임베딩 시간 단축 (1곡당 평균 20초 → 4초)
- 유사도 관계 재정의: 배치와 병렬 처리로 데이터 삽입 시간 단축 (52.14초 → 1.15초)
- 그래프 DB로 빠른 검색 제공, 데이터 간 관계를 직관적으로 표현
- 분류 모델 성능 비교 (Confusion Matrix), SR 모델 학습 결과 (PSNR, Loss)

추가 팁: 성능 차이를 잘 설명했더라도 테스트 결과의 근거(데이터셋, 조건, 측정 방법)를 함께 제시해야 신뢰도가 올라간다.

## 모바일

강조할 것
- **앱 성능 최적화**: 메모리 누수 방지와 객체 생명주기 관리. 데이터 압축으로 네트워크 사용량을 줄이거나 비동기 요청으로 반응성을 높인 사례
- **배포와 사용자 피드백 반영**: 배포 경험이 있으면 사용자 피드백과 반응. 피드백을 코드나 UI에 반영한 사례는 가산점
- **플랫폼별 최신 기술**: iOS는 SwiftUI, Combine, UIKit 등, Android는 Kotlin, Jetpack Compose 등 최신 기술 적용 사례

예시
- 데이터 저장 속도 개선: 데이터 청크와 병렬 처리, 임베딩 모델 변경 (2분 → 1분)
- 음성 인식 반응성 개선: 최소 음성 길이, 침묵 허용 시간을 조정해 인식 결과를 더 빨리 판단
- 사용자 피드백 반영: 데모와 릴리스 2회로 피드백을 모으고, 문의 사항을 버전 관리와 패치 노트로 운영

추가 팁: 개선 · 최적화 결과에는 항상 수치와 근거를 붙인다.
