# 포트폴리오 3단계: 작성 및 수정

1단계에서 모은 재료와 2단계에서 고른 키워드로 실제 포트폴리오 글을 쓰고 다듬는 단계다.

가이드가 강조하는 관점을 끝까지 붙든다. **포트폴리오는 기술 스택과 프로젝트의 나열이 아니라 "나의 성장 과정 이야기"다.** 신입은 경력으로 역량을 증명할 수 없으니, 실제로 해냈다는 증거(내가 만든 것, 겪은 문제와 해결, 수치로 본 결과)가 설득력을 만든다. 문장마다 읽는 사람이 "그래서 이 사람은 이걸로 무엇을 할 수 있는데?"에 답을 얻는지 본다.

## 진행 순서

### 1. 재료와 조건 확인

- `portfolio-notes/01-brainstorm.md`와 `02-keywords.md`를 읽는다. 사용자가 다른 자료(기존 포트폴리오, 이력서, README)를 주면 함께 쓴다.
- 앞 단계 파일이 없으면 이전 단계를 권하되, 사용자가 이대로 쓰자고 하면 대화와 자료에서 재료를 모아 진행한다.
- 아래 중 정해지지 않은 것만 한 번에 모아서 묻는다.
  - 지원 분야: 분야마다 강조할 내용이 다르다
  - 지원처 · 공고: 있으면 공고가 요구하는 역량에 맞는 경험을 앞에 둔다
  - 담을 형식: PPT, PDF, 노션, 웹 페이지 등. 형식에 따라 분량과 문장 길이가 달라진다

일부만 요청받으면 (예: "문제 해결 사례만 써줘") 그 부분만 같은 기준으로 쓴다. 이미 쓴 글의 검토만 원하면 4번(수정)으로 바로 간다.

### 2. 목차 구성

기본 목차는 가이드의 세 항목이다.

1. **프로필**: 슬로건, 한 줄 소개, 기술 스킬
2. **이력사항**: 교육, 수상, 자격증
3. **프로젝트** (프로젝트마다): 개요 → 담당 역할 · 기여도 → 사용 기술 → 문제 해결 사례

프로젝트 순서와 각 프로젝트에서 앞세울 사례는 2단계의 키워드 지도로 정한다. 지원 분야에 가장 맞고 근거가 강한 경험을 앞에 둔다. 목차를 짧게 보여 주고 사용자가 확인하면 본문으로 넘어간다. 본문을 다 쓴 뒤에 순서가 바뀌면 손이 두 번 간다.

### 3. 세부 내용 작성

`references/sections.md`를 읽고 항목별 기준대로 쓴다. 지원 분야가 정해졌으면 `references/field-tips.md`에서 그 분야 부분을 읽고 강조점을 맞춘다.

쓰는 동안 붙들 원칙:

- **내가 한 일이 주어다.** 팀 결과물 소개가 아니라 내가 맡고 기여한 것이 중심이다. "팀이 ~했다"가 많으면 "제가 ~했다"로 바꿀 수 있는지 본다.
- **기술에는 이유를 붙인다.** 무엇을 썼는지보다 왜 그것을 골랐는지가 판단력을 보여 준다.
- **결과는 수치와 전후 비교로.** 수치가 없으면 구체적인 방법으로 정성적 성과를 쓴다 (예: 팀 코드 컨벤션을 정해 중복 코드를 줄임).
- **모르는 사람이 읽어도 이해되게.** "관통 프로젝트", "싸피 금융망"처럼 교육 과정 안에서만 통하는 말은 바깥 사람이 알아듣는 말로 바꾼다.
- **사실과 수치를 지어내지 않는다.** 재료에 없는 숫자, 기간, 기여 비율은 `[확인 필요: 무엇]`으로 비워 둔다. 그럴듯한 숫자로 채우면 글은 좋아 보여도, 면접에서 근거를 물을 때 사용자가 곤란해진다.
- **보여 줄 자료의 자리를 표시한다.** 화면, 그래프, 다이어그램, 작동 영상이 들어가면 좋은 곳에 `[이미지: 무엇을 보여 줄지]`를 넣는다. 가이드는 변화를 눈으로 확인할 수 있게 하라고 거듭 권한다.

### 4. 수정

초안을 다 쓰면 두 번 훑는다.

**소리 내어 읽듯 읽기.** 한 문장씩 입으로 읽는다고 생각하고 걸리는 곳을 고친다.
- 한 호흡에 안 읽히는 긴 문장은 나눈다
- 같은 어미가 연달아 나오면 (~했습니다. ~했습니다. ~했습니다.) 바꾼다
- 주어가 흐릿하거나 조사가 어색한 곳을 고친다
- 설명 없이 나온 약어와 내부 용어를 풀어 쓴다

리듬이 어색한 곳은 귀로 들어야 잘 잡히므로, 사용자에게도 마지막에 한 번 직접 소리 내어 읽어 보기를 권한다.

**오타와 빠진 내용 점검.** `references/sections.md` 끝의 점검표로 확인한다.

### 5. 저장과 마무리

- `portfolio-notes/03-portfolio.md`에 쓴다. 이미 있으면 먼저 읽고, 사용자가 직접 고친 부분은 살린다.
- 채팅에는 짧게 알린다.
  - 파일 위치
  - 남은 `[확인 필요]` 목록: 사용자가 채워야 할 것
  - 넣으면 좋을 `[이미지]` 목록
  - 수정 단계에서 크게 바꾼 점 몇 가지
