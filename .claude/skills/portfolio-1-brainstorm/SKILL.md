# 포트폴리오 1단계: 생각 정리

포트폴리오가 막히는 건 대개 문장력보다 재료가 모자라서다. 이 단계의 목표는 하나, **나중에 고를 수 있을 만큼 재료를 넉넉히 쌓는 것**이다. 다듬기는 3단계에서 하니 여기서는 잘 쓰려 하지 않는다.

## 이 단계에서 지킬 것

- **걸러내지 않는다.** "별거 아닌데" 싶은 경험이 나중에 키워드의 근거가 되는 일이 많다. 실패한 시도, 작은 개선, 팀에서 맡은 궂은일까지 다 적는다.
- **사용자의 말을 그대로 적는다.** 2단계는 반복해서 나오는 표현으로 키워드를 찾는다. Claude가 문장을 다듬어 버리면 사용자가 실제로 자주 쓴 말이 사라지니, 받아 적을 때는 표현을 바꾸지 말고 자리만 정리한다.
- **평가하지 않는다.** "이건 포트폴리오에 넣기 약해요" 같은 말을 들으면 사용자는 꺼내는 이야기를 줄인다. 고르는 건 2·3단계의 일이다.
- **수치와 사실을 지어내지 않는다.** 모르는 숫자는 `[나중에 확인: 무엇]`으로 비워 둔다. 지어낸 수치는 면접에서 근거를 물을 때 그대로 위험이 된다.

## 진행 순서

### 1. 작업 파일 준비

- 사용자가 위치를 정하지 않았다면 현재 작업 폴더의 `portfolio-notes/01-brainstorm.md`를 쓴다. 처음 만들 때 저장 위치를 한 줄로 알린다.
- 파일이 이미 있으면 읽고 이어서 채운다. 지난번에 모은 재료가 사라지지 않도록 덮어쓰지 않는다.
- 지원 분야(프론트엔드 · 백엔드 · 임베디드 · AI/데이터 · 모바일 등)와 지원처를 알면 파일 맨 위에 적는다. 모르면 나중에 물어도 된다.

### 2. 있는 자료부터 훑기

질문하기 전에 이미 있는 자료에서 사실을 먼저 모은다. 사용자의 수고가 줄고, 질문은 기억해야만 답할 수 있는 것에 집중할 수 있다.

- 사용자가 준 자료: 프로젝트 README, 발표 자료, 회고, 기존 이력서 · 포트폴리오, 노션 내보내기 등
- 소개할 프로젝트의 저장소가 이 컴퓨터에 있으면 경로를 물어 README와 설정 파일(package.json, build.gradle 등)로 기술 스택을 보고, `git config user.name`으로 이름을 확인한 뒤 `git log --author`로 본인 커밋을 훑는다
- 찾은 것은 출처와 함께 "자료에서 찾은 것"에 적는다. 다만 왜 그렇게 했는지, 무엇이 어려웠는지는 자료에 없으니 질문으로 채운다

자료가 없으면 건너뛰고 바로 질문한다.

### 3. 질문으로 끌어내기

먼저 "포트폴리오에 넣고 싶은 것, 떠오르는 것 아무거나 편하게 적어 주세요. 막히면 제가 질문할게요"처럼 자유롭게 쏟아낼 자리를 연다. 가이드가 말하는 브레인스토밍이 이것이다.

그다음 질문은 한 번에 2~3개씩 한다. 목록을 통째로 던지면 답이 짧아진다. 답이 나오면 받아 적고, 흥미로운 대목은 꼬리 질문으로 더 판다.

- "그 문제는 어떻게 알아챘어요?"
- "바꾸기 전과 후가 얼마나 달라졌어요?"
- "다른 방법도 있었을 텐데 왜 그걸 골랐어요?"

아래는 빠뜨리지 않기 위한 목록이지 순서가 아니다. 사용자가 편한 쪽부터 간다.

**나 (프로필 재료)**
- 개발할 때 가장 신경 쓰는 것, 꼭 지키려는 것
- 팀원이나 주변에서 나에 대해 자주 하는 말
- 가장 자신 있는 기술과, 그걸로 실제로 만들어 본 것
- 요즘 가장 깊게 파고 있는 기술
- 1년 뒤, 3~5년 뒤 되고 싶은 개발자의 모습

**이력 (이력사항 재료)**
- 교육: 기관, 기간, 총 시간, 배운 것, 수행한 프로젝트 수
- 수상: 대회 · 프로젝트 이름, 상, 주최, 날짜, 무엇을 만들어 받았는지
- 자격증 · 어학: 이름, 등급, 취득일
- 전공, 멘토링, 스터디, 대외활동

**프로젝트 (교육 과정 · 개인 · 해커톤 · 공모전 모두, 프로젝트마다)**
- 왜 만들었나: 배경, 누구를 위한 서비스인가, 목표
- 주요 기능 몇 가지
- 내가 맡은 것: 기능 · 화면 · 모듈, 기여 비율, 팀 인원과 기간
- 쓴 기술과 고른 이유 (다른 선택지와 비교했다면 그 이유까지)
- 막혔던 순간: 무엇이 문제였고 어떻게 알아챘나
- 어떻게 풀었나: 시도한 방법들, 최종 방법, 그 방법을 고른 이유
- 결과: 수치(속도, 용량, 정확도, 시간), 전후 비교, 사용자 반응, 수상
- 새로 배워 적용해 본 기술, 도전한 시도 (꼭 "문제"가 아니어도 된다)
- 아쉬운 점, 다시 한다면 바꿀 것

### 4. 받아 적기

질문 묶음 하나가 끝날 때마다 파일에 덧붙인다. 대화가 중간에 끊겨도 재료가 남는다. 틀은 아래를 쓰고, 칸을 다 채울 필요는 없다.

```
# 생각 정리

- 지원 분야 / 지원처:
- 마지막 수정: YYYY-MM-DD

## 나
- (사용자의 표현 그대로)

## 이력
-

## 프로젝트: <이름>
- 기간 / 인원 / 내 역할:
- 배경 · 대상 · 목표:
- 내가 만든 것:
- 쓴 기술 · 고른 이유:
- 문제 · 도전
  - 무엇이 문제였나:
  - 어떻게 풀었나:
  - 결과:
- 그 밖에 떠오른 것:

## 자료에서 찾은 것
- (내용) — 출처:

## 나중에 확인
- [ ]
```

### 5. 마무리

재료가 충분한지 짧게 점검한다. 비어 있는 곳이 있으면 한두 개만 더 묻고, 사용자가 그만하자고 하면 거기서 멈춘다.

- 나: 강점이나 가치관이 드러나는 말이 하나 이상 있는가
- 프로젝트마다: 내가 맡은 것, 문제 · 도전 사례 하나 이상, 결과 하나 이상이 있는가

끝으로 채팅에 짧게 알린다: 넉넉한 곳과 빈 곳, 파일 위치, 다음 단계 `/portfolio-2-keywords`.
