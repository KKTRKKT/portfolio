04 — Trouble-shooting

문제 해결

원인을 어떻게 확인했는지까지 적었습니다.

COIP

Pod을 늘릴수록 DB 커넥션이 먼저 바닥남

원인
HPA로 늘어난 Pod마다 따로 잡은 풀이 합쳐져 max_connections에 도달
해결
PgBouncer transaction mode(pool_size=25)로 풀을 한 계층에 집약
결과
커넥션 점유 5xx 사실상 제거, DB 증설 없이 Pod 확장

검증 스파이크 구간 로그를 분석해 5xx의 가장 잦은 원인이 풀 고갈임을 먼저 확인

SSAFY 김밥 지옥

새로고침하면 빈 방으로 들어옴

원인
새 연결이 먼저 붙고 옛 연결의 끊김이 늦게 도착해, 돌아온 사람을 끊김으로 덮어씀
해결
같은 사람의 소켓이 살아 있으면 끊김을 무시하고, 게임이 없으면 사유와 함께 로비로 안내
결과
새로고침 뒤 원래 자리로 복귀, 재현 시나리오를 e2e로 고정

검증 "유예가 짧다"는 첫 가설로 30초로 늘렸다가, 브라우저 재현에서 1초 새로고침도 10초 안에 복귀하는 것을 보고 되돌림

커미조아

월간 통계에 하루 이상 걸림

원인
통계를 매번 원장 풀스캔으로 집계
해결
Spring Cache 적용과 집계 테이블 분리
결과
통계 산출 즉시, 관리대장 10종을 한 화면에서 운영

검증 입고부터 통계까지 전 흐름을 단위와 통합 테스트 파이프라인으로 보장

KISTI

9개 모듈에 흩어진 다기관 인증

원인
모듈마다 로그인과 권한 정보가 따로 있어 사용자 경험과 감사 모두 불편
해결
SAML2 SSO 모듈(kafe)을 직접 개발하고 Redis 세션으로 9개 모듈이 세션을 공유
결과

06 — AI workflow

AI 활용

AI가 한 일보다, 확인하는 구조를 설계했습니다.

  1. /be-onboard현황 파악구조, 규칙, 내 이슈를 읽고 브리핑. 확인 안 된 규칙은 "정해지지 않음"
  2. /be-issue이슈 선택스프린트 이슈를 보여 주고 대기. 임의로 고르지 않음사람이 선택
  3. /be-plan계획파일 단위 변경, 테스트 계획, 모르는 것, 범위 밖을 적고 멈춤명시적 승인
  4. /be-dev구현코드와 테스트를 함께. 실제 실행 출력을 보여 줌
  5. /be-mr검수와 MR변경 요약, 테스트 결과, 비밀값 검사 후 대기push 전 승인
도구 선택: ECC (Everything Claude Code)

AI에게 코드를 맡길수록 "실제 팀에서 하듯이" 테스트와 리뷰를 거치게 하는 게 중요하다고 봤습니다. ECC는 테스트 우선 개발, 언어별 코드 리뷰, 검증 루프가 스킬과 에이전트로 갖춰져 있어, AI 작업을 현업 개발 절차에 맞추기 위해 채택했습니다.

  • 테스트 먼저TDD 워크플로로 실패하는 테스트를 먼저 쓰고, 통과시킨 뒤 커버리지를 확인하는 순서를 AI에게 지키게 함
  • 커밋 전 리뷰TypeScript, Python 등 언어별 리뷰 에이전트로 변경분을 한 번 더 검토한 뒤 커밋
  • 근거부터 요구AI가 파일을 만들거나 고치기 전에 호출처와 지시 내용을 먼저 밝히게 하는 훅을 켜 둠
  • 비용 관리세션별 사용 비용을 기록해 무거운 작업과 가벼운 작업을 구분
