주요 구현 사례

기능문제해결결과
실시간 배틀런같은 티어 상대와 달리며 WebSocket으로 주행 거리를 1초 주기로 실시간 통신합니다. 15초 안에 상대를 찾지 못하면 고스트와 달립니다.동시 매칭 요청 시 경쟁 상태(Race Condition)로 같은 사람이 중복 배정되거나, 대기를 취소한 사람과 매칭될 수 있었습니다.대기 상태 검증과 상대 배정을 단일 Redis Lua 스크립트로 원자적(Atomic) 처리해 두 단계 사이의 경쟁 상태를 차단했습니다.20명이 동시에 대기해도 정상 매칭되며, 다수 요청이 같은 상대를 선택해도 한 번만 배정되는 것을 동시성 테스트로 검증했습니다.
크루런크루원이 대기실에서 준비하고 함께 출발해, 달리는 동안 실시간 순위를 확인합니다.주기적 폴링(Polling) 시 크루원 수에 비례해 요청 부하가 증가하고, 트랜잭션 커밋 전 알림 발행 시 앱이 이전 상태를 조회하는 정합성 문제가 있었습니다.트랜잭션 커밋 이후 변경 항목과 대상 ID를 푸시해 해당 화면만 재조회하도록 하고, 폴링은 연결 단절 시의 결과 화면에만 남겼습니다.에뮬레이터 2대와 계정 3개로 목록, 대기실, 자동 출발, 중간 참여, 결과를 확인하는 자동화 통합 테스트 8건을 통과했습니다.
셀카 아바타 생성AI가 셀카로 아바타 얼굴을 만들고, 앱은 작업 상태를 확인해 완성된 얼굴을 가져옵니다.실기기 테스트에서 약 300초에 실패로 표시됐지만, 이미지는 345초에 저장됐습니다. 같은 사진으로 재요청해도 이전 실패 작업이 반환됐습니다.Node 중계 서버의 HTTP 기본 타임아웃(300초)으로 연결이 조기 종료되었습니다. 타임아웃을 15분 생성 한도에 맞게 조정하고, 지연 저장된 결과는 재조회로 회수하며 확정 실패 후 재요청 시에만 신규 작업을 생성하게 했습니다.타임아웃을 200ms로 단축한 테스트에서 지연 응답 처리와 결과 회수 동작을 검증했습니다.
디자인 시스템앱 전반의 화면 일관성을 유지하기 위해 Material Design 3 기반 디자인 시스템을 구축했습니다.여러 화면을 병행 개발하면서 색상, 모서리 반경, 서체, 버튼과 칩 스타일이 화면마다 달라질 수 있었습니다.Material Design 3(RunkkTheme)의 색상, 서체, 도형 토큰을 정의하고, 이에 맞춰 버튼, 칩, 배너, 지표 타일 등 공통 컴포넌트를 설계해 화면에 적용했습니다.전 화면의 UI 일관성과 재사용성을 확보했고, 컴포넌트 동작, 접근성 테스트와 스크린샷 테스트로 일관성을 검증했습니다.
기록 대결내 최고 기록이나 코치 기록을 상대로 달립니다. 앱은 출발 시 받은 경과 시간별 누적 거리 테이블을 직선 보간해 상대 위치를 산출합니다.클라이언트(Kotlin)와 서버(Java)가 위치 보간 로직을 이원화해 계산하면서 화면 표시와 최종 승패 판정이 어긋날 위험이 있었습니다.입력과 기대 출력을 단일 파일로 공유하는 계약 테스트(Contract Test)를 양쪽에 적용해 같은 기준을 쓰게 했습니다.앱이나 서버의 계산 결과가 기대값과 다르면 테스트가 실패해 불일치를 즉시 탐지하도록 했습니다.
워치 앱워치로 혼자 달릴 수 있고, 폰으로 달릴 때는 워치에서 거리 차이와 추월 알림, 근접 진동을 확인합니다. 폰과 워치는 Wearable Data Layer API로 연동합니다.근접 알림 종료 이벤트가 유실되면 워치 진동이 멈추지 않을 수 있었습니다.폰은 근접 상태가 이어지는 동안 2초 주기로 하트비트 신호를 송신하고, 워치는 마지막 신호 수신 후 3초 타임아웃이 경과하면 진동을 자동 종료하도록 구현했습니다.2초 주기 송신 시 진동이 유지되고, 신규 신호 없이 3초가 경과하면 종료되는 것을 워치 테스트로 검증했습니다.

주요 구현 사례

기능문제해결결과
DB 연결 관리다중 Pod 환경에서 PgBouncer로 DB 커넥션을 재사용합니다.Pod 확장 시 각 인스턴스의 커넥션 풀이 누적되어 PostgreSQL 최대 커넥션 한도에 도달하는 것을 로그에서 확인했습니다.Pod 수와 DB 커넥션 수를 분리하기 위해 PgBouncer로 트랜잭션 단위 커넥션 풀링을 적용했습니다.DB를 증설하지 않고 Pod를 확장할 수 있게 했습니다.
실시간 차트Upbit 시세로 캔들 차트와 보조지표를 그리는 기능입니다.시계열 캔들 데이터의 36일 결측 구간(Gap)을 놓쳤고, 대량 거래량은 부동소수점 정밀도 문제로 소수점 이하가 절사되어 Upbit 원본과 오차가 발생했습니다.캔들 연속성 검사와 일간 대조 검증을 추가하고, 거래량은 Decimal로 읽어 DB와 같은 소수 자릿수로 정밀도를 맞췄습니다.36일 결측 구간 감지를 테스트하고, PostgreSQL에 저장된 거래량이 원본과 일치하는지 검증했습니다.
자동매매와 캔들 동기화Upbit 캔들을 모아 전략을 평가하고, 조건에 맞으면 모의 주문을 냅니다.최근 24시간 확정 손실 한도 도달 시 청산, 예약금 해제, 중단 상태 저장이 분리되어 부분 실패 시 상태 불일치로 전략이 재실행될 수 있었습니다.킬스위치의 청산 처리, 예약금 해제, 전략 중단 상태 저장을 단일 트랜잭션으로 원자적 처리했습니다.킬스위치 발동 시 전략이 중단되고 예약금이 해제되는 것을 테스트로 검증했습니다.
현물 주문과 체결시장가와 지정가로 암호화폐를 모의 거래하는 기능입니다.동시 주문 요청이 들어와도 같은 잔고를 중복으로 쓰지 않고, 체결 내역과 잔고 정합성을 일치시켜야 했습니다.DB 락(Lock)으로 잔고를 잠근 뒤 주문 금액과 코인 수량을 예약하고, 체결 시 단일 트랜잭션에서 체결 내역과 잔고를 갱신했습니다.주문 취소 시 예약이 해제되고, 체결 시 잔고 정합성이 유지되는 것을 테스트로 검증했습니다.
백테스트여러 지표를 조합한 매매 전략을 과거 시세에 적용하는 기능입니다.이동평균선의 교차나 여러 지표의 조건을 함께 평가하려면, 지표마다 다른 출력값과 단위를 구분해야 했습니다.지표의 출력값과 비교 대상을 규칙으로 만들어 AND나 OR로 조합했습니다. 공통 지표 연산 모듈을 재사용하고, 단위가 다른 지표끼리는 비교를 차단했습니다.CCI와 RSI 조건을 하나로 묶은 전략도 과거 시세에서 수익률과 체결 내역을 확인할 수 있게 했습니다.
AI 전략 어시스턴트사용자가 말로 설명한 매매 조건을 전략 초안으로 바꿉니다.AI가 지원하지 않는 지표나 연산자를 만들 수 있어, 생성된 조건을 전략에 쓸 수 있는지 확인해야 했습니다.기존 전략과 같은 규칙 검사로 지표와 연산자를 검증했습니다. 검증을 통과한 초안만 보여 주고, 사용자가 선택한 경우에 전략을 저장했습니다.지원하지 않는 조건을 거부하고, 초안 생성만으로 전략이 저장되지 않는 것을 테스트로 검증했습니다.

개요

시스템
수기로 관리하던 입고와 검사, 품질 이력을 한 화면에서 관리하는 시스템입니다.

주요 구현 사례

기능문제해결결과
관리대장 통합여러 품질 관리대장을 한 시스템에서 관리합니다.품질 기록을 남기려면 종이 양식을 준비해 손으로 작성하고, 작성한 양식을 스캔한 뒤 엑셀에 정리해야 했습니다. 관리대장 10종도 흩어져 있었습니다.흩어진 관리대장 10종을 단일 도메인 모델로 통합해 시스템 화면에서 기록을 바로 입력하도록 하고, 시리얼 번호 변경 이력을 추적할 수 있게 저장했습니다.네 단계에 걸치던 기록 절차가 시스템에 한 번 입력하는 방식으로 줄었습니다. 시리얼 번호 변경 이력도 조회할 수 있게 했습니다.
월간 통계품질 대시보드의 월간 통계를 조회합니다.관리대장이 개별 엑셀 파일로 흩어져 있어, 월간 통계를 내려면 수작업으로 취합하느라 하루 이상 걸렸습니다.흩어진 관리대장 데이터를 중앙 DB에 적재하고, QueryDSL 기반 동적 집계 조회와 대시보드를 구현했습니다.하루 이상 걸리던 통계를 화면에서 바로 조회할 수 있게 했습니다. 입고부터 통계까지 단위 테스트와 통합 테스트를 작성해 정합성을 검증했습니다.
